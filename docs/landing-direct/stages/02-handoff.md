# Handoff этапа 2: статичная `/landing-direct/`

**Статус:** отдельная статичная страница собрана; браузерная визуальная приёмка остаётся оркестратору. Код не коммитился и не публиковался.

## Файлы

- `webApp/src/components/v3/DirectLanding.astro` — новая разметка, данные шести секций, контакты и компактный footer.
- `webApp/src/styles/direct-landing.css` — только локальная адаптивная стилизация.
- `webApp/src/pages/landing-direct.astro` — route теперь импортирует новый компонент.

Существующие `CampaignLanding.astro`, `campaignLandings.ts`, общий campaign CSS, главная, `v3.css`, `V3Motion.astro` и WOW не изменялись в этом этапе. Рабочий каталог был dirty до работы; baseline — `tmp/landing-direct-orchestration/`.

## Реализация

- Hero во всю ширину `v3-shell`: постоянный `/assets/v3/sergey-kryukov.png` за обычным HTML текстом; слева scrim, справа портрет. H1, цена, срок, условие начала и CTA присутствуют до JS. `data-direct-hero`, `data-direct-scene`, `data-direct-poster`, `data-direct-canvas` и класс canvas `.is-ready` подготовлены для этапа 3; canvas сейчас скрыт, покадрового скрипта нет.
- После визуальной проверки 1366×768 добавлен локальный верхний отступ под фиксированную навигацию: 5.25rem на desktop и 4.5rem до 36rem. В компактном hero внутренний верхний отступ сокращён, чтобы не уводить CTA ниже первого экрана.
- Порядок секций: hero, состав/маршрут, кейсы, процесс, FAQ, контакт/цена. Copy взята из `03-design-spec.md`; рекламный бюджет явно указан отдельно.
- Кейсы берут `projects[4]`, `[3]`, `[2]`: Росснаб73, Промышленные альпинисты, СЭС МСК. Используются текущие описание, ссылка и три изображения устройств каждого проекта.
- FAQ использует нативные `details/summary`. Контакты: действующие Telegram, MAX и mailto с темой существующей кампании.
- `BaseLayout` задаёт canonical `/landing-direct/` и `noindex=true`. Общий Footer сразу повторял бы большой CTA после контакта, поэтому вместо него локальный компактный footer с действующими именем, навигацией и контактами.

## Проверки

- Из `webApp`: `ASTRO_TELEMETRY_DISABLED=1 node ../node_modules/astro/bin/astro.mjs check` → 37 файлов, 0 errors, 0 warnings, 19 существующих hints (baseline: 36 файлов и те же диагностические числа).
- `GET http://localhost:4321/landing-direct/` → 200. В HTML обнаружены H1, 35 000 ₽, poster, FAQ, `noindex,follow`; JSON-LD отсутствует.

## Следующий этап и риск

Оркестратор проверил 1440×900 и 390×844: композиция хорошая, горизонтального overflow нет, CTA виден. На 1366×768 выявлено перекрытие kicker фиксированной навигацией; локальный отступ добавлен, повторный скриншот ожидается. Остальные ширины, keyboard focus и скорректированный первый экран проверить при приёмке. Визуальные проверки выполняет оркестратор по условию разделения этапов. После приёмки статичной композиции этап 3 добавляет локальную покадровую сцену, сохраняя poster и доступность без JS.
